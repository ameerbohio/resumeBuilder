# Bullet ordering: relevance/impact priority best practice

Generic guidance on how to order bullets within a role or project section
once the set of bullets is already decided — a separate question from
which bullets to include or how to word them.

## Core principle

Lead with the most relevant and impressive bullet in each section, not
the most recent or most senior-sounding one. Recruiters give the top of
each section the most attention (a few-second scan), so the first bullet
does the most work toward "keep reading."

## Scoring framework for ranking bullets

Score each bullet on three axes, then rank high-to-low within its
section:

1. **JD relevance** — does it use the JD's own keywords/phrases, or map
   directly to a Required/Highly-Valued/Strong-Plus item or a line in the
   JD's own "what you'll do" list? A near-verbatim echo of the JD's own
   phrasing (not just a thematic match) ranks higher than a loose
   thematic tie.
2. **Quantified impact** — a concrete number outranks a process/scope
   statement with no metric, all else equal.
3. **Scope appropriateness** — for a JD framed as a growth/mentee seat,
   individual-contributor language should generally rank above
   ownership/leadership language ("led," "owned," "primary"), since
   leading with the most senior-sounding bullet is exactly what
   front-loads the overqualification read a recruiter would form in the
   first few seconds.

When the JD itself lists responsibilities in a specific order (most
postings do — "what you'll do" sections read highest-to-lowest
priority), mirror that order for ties: a bullet matching the JD's #1
listed responsibility should generally lead over one matching its #3 or
#4, even if their quantified-impact/scope scores are similar.

## Exceptions

- **Overview/context bullets stay first regardless of relevance score.**
  A project section that opens with "here's what this project is" before
  diving into specific technical highlights reads better than opening
  mid-detail — narrative coherence overrides strict relevance ranking for
  a section's first bullet if that bullet's job is orientation, not proof.
- **Role/project order itself (reverse chronological) is untouched by
  this.** This is about bullet order *within* a role or project, not
  which role or project comes first.
