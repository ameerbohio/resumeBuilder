# Metric/quantification density in bullets: best practices

Researched while raw-score-checking a compact draft for headroom before
further compaction. Generic guidance only — application-specific audits
using this benchmark belong in that job's own
`1-job-descriptions/<slug>/research.md`, not here.

## Bullet formula

- **Action + Tech + Scope + Result** — every strong bullet names a verb,
  the specific technology/technique, the scope owned, and a measurable
  result. Most sampled examples close on a trailing number
  ("...reducing deploy time by 45%").
- Target density: **3-6 metric-bearing bullets per role**, front-loaded
  with the highest-impact ones. Not every bullet needs a number, but a
  role with zero is an outlier against this benchmark.
- Metric categories to mine when a bullet feels number-less: performance
  (latency, load time, throughput), scale (users served, requests
  handled, data processed), reliability (uptime, crash rate, incident
  count), delivery (release frequency, deploy time), cost/quality (spend,
  defect rate, test coverage). Also headcount-adjacent: services owned,
  engineers reviewed, pages/systems migrated, % of tests added.
